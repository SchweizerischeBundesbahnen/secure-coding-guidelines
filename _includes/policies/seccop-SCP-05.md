{% if include.tier and include.tier == true %}<!-- markdownlint-disable MD041 -->![MUST](https://img.shields.io/badge/MUST-ff0000.svg) {% endif %} **SCP-05: Consider the security of all user input data paths**

A user input data path is any path that user input data takes from the point it enters the application until it is consumed by a function.
Note that functions which consume inputs generated by a function that processed user input data must also be considered.
In particular, it is imperative to consider all possible paths where a user can in some way influence the data that is consumed by a function.
For this, it must be ensured that the data is properly validated and/or encoded before being used by the function, or that a secure function is used.
These paths include those that are not commonly used, such as error handling paths, paths related to logging mechanisms, or paths that are only used in specific configurations.
In case information is stored in logs or databases, additional paths must be considered and properly secured.
When a user can directly influence the data stored in a database, this data must be considered tainted and non-trustworthy.
Vulnerabilities that result from processing data that was previously stored in a database or log file are considered second-order vulnerabilities, and must also be considered.
